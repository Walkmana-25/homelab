## Research Results: Harbor Helm Chart Deployment on k3s

**summary:**
Researched the official Harbor Helm chart for deployment on this k3s cluster. The official chart lives at `https://helm.goharbor.io` (chart name `harbor`); the **latest stable is v1.19.1 → Harbor OSS 2.15.1** (pin this, not 1.19.0 which has a Docker Hub proxy-cache bug). I cross-referenced the chart's full `values.yaml` against this repo's existing ArgoCD patterns and produced ready-to-use, YAML-validated `values.yaml` + ArgoCD `Application` manifests. Key architectural insight: this cluster routes web UIs through a `cloudflare-tunnel` ingress class, but Harbor (a docker registry) should use the **Traefik** ingress class (k3s default) + cert-manager — Cloudflare Tunnel isn't suited to large container-layer uploads.

**key_findings:**
- **Chart**: `repoURL: https://helm.goharbor.io`, `chart: harbor`, `targetRevision: 1.19.1` (Harbor 2.15.1). Fallback `1.18.4` (2.14.4).
- **Modern Harbor has NO notary / chartmuseum** — both were removed in Harbor 2.x. Current components: core, jobservice, registry, portal, trivy, database (Postgres), redis (Valkey), exporter. Don't look for those values.
- **cert-manager integration** = `expose.tls.certSource: secret` + `expose.tls.secret.secretName: harbor-k3s-tls` + annotation `cert-manager.io/cluster-issuer: letsencrypt-prod`. cert-manager creates/populates the secret; Harbor's ingress references it. ⚠️ **No ClusterIssuer is committed in git** — verify the real name with `kubectl get clusterissuer` (I used `letsencrypt-prod` as placeholder).
- **NFS storage**: the cluster's `nfs` storage class (nfs-subdir-external-provisioner, `reclaimPolicy: Retain`, `defaultClass: true`) is applied to all 5 PVCs (registry/jobservice/db/redis/trivy). Use `updateStrategy: Recreate` to avoid RWO double-mount races on NFS.
- **Postgres-on-NFS is the top gotcha** — locking can occasionally corrupt the DB under load. Cluster already has **cloudnative-pg** and **longhorn** as escape hatches if internal-postgres-on-NFS misbehaves.
- **ArgoCD pattern**: matches repo convention — `spec.source.helm.values: |` (string block, dominant style here), sync-wave `3` (after cert-manager@0, nfs@1). Place at `argocd/k3s/apps/application/harbor/application.yaml`, add `- harbor` to the kustomization.
- **Security**: 3 `CHANGE-ME` placeholders (`harborAdminPassword`, `secretKey` 16-char, `database.internal.password`) — replace before applying, ideally via the in-cluster SealedSecrets.
